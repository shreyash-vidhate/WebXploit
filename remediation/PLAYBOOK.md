# WebXploit Remediation Playbook

## A01 — Broken Access Control
Enforce authorization on every protected resource server-side; never rely on the client to hide admin functions.

## A02 — Cryptographic Failures
Do not expose backup/configuration files. Remove secrets from deployable artifacts and restrict static-file paths.

## A03 — Injection
Use parameterized queries/ORM binding, server-side input validation, and generic authentication errors.

## A04 — Insecure Design
Validate business invariants server-side, including positive quantity and permitted state transitions.

## A05 — Security Misconfiguration
Disable directory listing and remove unnecessary files/routes. The WAF rule is a compensating control, not a replacement for the application fix.

## A06 — Vulnerable Components
Inventory dependencies, track versions/advisories, patch outdated components, and add dependency checks to CI.

## A07 — Authentication Failures
Apply rate limiting, progressive delays, MFA for privileged access, and monitoring of repeated failures.

## A08 — Data Integrity Failures
Validate authorization and integrity of role/state changes server-side; never trust client-supplied privilege fields.

## A09 — Logging Failures
Use structured logging and encode/control user-supplied values before writing them to logs.

## A10 — SSRF
Use strict allowlists for outbound destinations, block metadata endpoints, and validate URLs after parsing. WebXploit's lab uses only a Docker mock metadata endpoint.
